# ATH-002 — Autorização, isolamento e validação

**Prioridade:** P0.2. **Dependências:** ATH-001. **Estado:** Concluída.

## Problema e resultado

O núcleo tem verificações de membership, mas faltam provas abrangentes com banco real. Cobrir e corrigir acesso cruzado a projetos, US, pastas, templates, comentários, relações, referências, membros e notificações. Alinhar a matriz de três papéis: `VIEWER` pode comentar; só `OWNER`/`EDITOR` editam; só `OWNER` administra membros/projetos.

## Aceite

- Testes de integração com PostgreSQL real exercitam cada papel e usuário de outro workspace, inclusive IDs conhecidos de recursos alheios.
- Último Owner não pode ser removido ou rebaixado, mesmo em concorrência; ações de membros não ampliam permissões indevidamente.
- Documentos TipTap rejeitam HTML bruto, atributos/nós desconhecidos, links inseguros e tamanho acima de 256 KB; DTOs rejeitam entradas inválidas relevantes.
- Conflito de revisão devolve 409 com `details.currentRevision`, inclusive em corrida entre duas sessões.
- Código `US-###` permanece único sob criação simultânea.

## Verificação

Usar banco de teste isolado, aplicar migrations e executar casos de permissão/persistência; depois `test`, `build`, `lint`. Não reutilizar banco com dados do usuário.
